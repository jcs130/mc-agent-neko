# 动作失败反馈、批次边界与学习能力

此文记录当天较早交付的状态。随后已开启并修复代码生成与按需视觉路径；下文的“五轮尝试”“生成代码关闭”和未修复 lockdown 均为当时状态。最新部署、三轮上限与 CPU 视觉编码见[本机代码与视觉能力](neko-local-code-and-vision-2026-10-09.md)。经验记忆不等于自动技能晋级或模型训练，这一限制仍然成立。

## 已定位的运行问题

背包整理曾一次生成多条 `!discard`。`discardAway` 在物品反弹或重新拾取后返回 false，但命令包装层丢弃了这个返回值，只返回动作日志。日志末尾又可能是“已回到原位置”，于是失败看起来像正常执行。批次执行器只检查空返回值，收到非空失败文字也继续执行后续丢弃，直到任务时限。

另一条链路是自保重复进入：看门狗清除了 `mode.active`，正在 await 的旧动作却尚未结束。同一自保再次调用 `runAction`，尝试中断自身，最终可能触发 `action-refused-stop` 重连。旧 finally 使用当前 `agent.bot` 释放所有权，也可能误碰重连后的身体。

## 本次修正

- 命令包装保留明确的 false、执行异常及超时，返回本地 `Action failed:`；未启动的前置检查返回 `Action not started:`。已覆盖丢弃、装备、坐标导航、回地面、合成、就地放置和箱子存取。
- 批次遇到参数拒绝或上述明确失败标记时停止，剩余命令不执行。实际失败与未执行数量进入模型历史，下一次有额度的模型回合可以据此换方法。
- 默认批次从六条缩为三条；保留既有环境变量覆盖。累计到 30 秒时，在当前动作真正完成后让模型重新判断，不强行截断正在正常执行的技能。
- 不按任意“failed”关键词判断批次失败：服务器或玩家文字、内部曾失败但最终成功的恢复日志，不应变成程序控制指令。
- 每次反射绑定原身体和独立调用标记。同一反射尚未退出时合并重复进入；其他反射仍可通过原仲裁规则处理危险。重连初始化清除旧身体的标记，旧回调不会清除新调用的活跃状态、释放新身体所有权或代它重新提示模型。

这些修改针对已复现的失败反馈和重复进入，不代表修复了所有寻路问题、服务器物品同步或所有动作取消竞态。真正卡死的动作仍保留现有取消、任务时限与重连兜底。

## 当前是否支持新脚本和自我进化

| 能力 | 源码与当前状态 |
| --- | --- |
| 模型生成动作脚本 | `src/agent/coder.js` 的 `!newAction` 路径调用 code_model 生成 JavaScript，写入 `bots/<name>/action-code/`，检查语法/函数引用/lint，并能把运行错误反馈给模型。最多五轮尝试。 |
| 目前能否使用生成代码 | 试跑配置 `allow_insecure_coding=false`，且 `blocked_actions` 包含 `!newAction`。本次保留这两个设置。code_model 已配置成本机 Qwen，但配置模型不等于开启工具。 |
| 复用现有技能 | `!runSkill` 使用现有自定义技能目录。`skill_library.js` 扫描 `bots/_supervisor/skills/`，使用同一目录生成可调用清单，约五分钟后台刷新。可信开发者新增合适的模块后可被发现。 |
| 保存游戏经验 | 已启用原生记忆总结，把历史观察归纳并持久化，目标包括配方、服务器规则、失败条件和沟通事实。它仍是可能出错的模型摘要；当前任务与新鲜状态优先。 |
| 自动积累新技能 | 生成代码保存为执行/调试文件，不会自动经过验收、注册为可复用技能或建立成功率排名。 |
| 自我修改/模型进化 | 当前没有经验证的自动改源码、离线评测、技能晋级/淘汰、版本回滚或模型权重训练闭环。错误反馈重试与经验记忆不能当作完整自进化。 |

代码生成路径虽包含 SES compartment，但不能据此宣称已具备可靠的安全隔离。源码审计还发现 `library/lockdown.js` 的同名包装调用会回到自身，且配置含 unsafe 选项；本次没有启用或改造该路径。

若以后实现技能自我改进，候选代码需要独立保存版本与来源，先做离线验证，再依据实际回执确认效果；通过验收后才注册技能，保留失败记录和回滚版本。服务器文字不能触发修改执行器或提升权限。当前交付未实现该流程。
