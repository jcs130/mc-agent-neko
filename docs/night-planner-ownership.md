# 夜间避险与外部主脑的行动权

本地部署优化：夜晚是 Neko 制订计划时的风险信息，不能单独成为反射层
占用身体直到天亮的理由。此修改针对 `external_autonomy_owner=neko`
或已连接的正式游戏信息控制客户端；独立原生 Agent 保留原夜宿策略。

审查了三条不同路径：原生 Kernel 已通过外部所有权门让位，其世界模型
中的 `NIGHT_SEAL` 提案不等于实际派发；本次修改实际执行的反射层。
`nightShelter` 以及 `prepNether` 中主动选用的夜宿流程属于明确技能任务，
继续响应停止和受击，保留原契约；没有将主动选择休息与反射强制停工混为
同一开关。时间、真实威胁与地形继续进入游戏信息，不删除夜间观测。

## 回归报告 / Regression Report

**证据。** 2026-10-11 北京时间约 16:43–16:48 的 160 帧连续观测中，
生命和饥饿均为 20，最大位移约 2.37 格，库存未改变；身体在
`mode:self_preservation` 和 `mode:mobility` 间切换。夜间保护不是一个
僵死标签：真实守卫不断重启等待。天亮后又看到村庄建筑的精确保护拒绝
和 `enchantments.concat is not a function`。之后自然运行回到地表，
因此“从未能移动”或“服务器故障”均不符合证据。

**假设。** 外部主脑的任务租约间隙仍会触发原生预防夜宿；同一个安全的
保护区恢复窗口只约束逃跑，没有约束被动夜间等待与机动挖掘。另一个
独立故障是 1.20.6 物品组件的附魔对象被当作数组，导致挖掘计时失败。
附近出现末影人并不足以证明它是服务器 NPC，本次没有添加猜测性白名单。

**改动。**

- `shouldNightShelter(bot, agent)` 在外部主脑负责自主规划时放弃预防性
  抢占，包括两次任务之间。实际受击后的逃跑、近距苦力怕、战斗、溺水、
  火和坠落分支继续独立工作。未将所有 `self_preservation` 一概视为空闲。
- 原本已有的保护区恢复条件被动等待和机动反射共同遵守：精确地板拒绝、
  至少 15 秒与三次无进展观测、健康安全才给 60 秒规划窗口；真实受击、
  近距苦力怕、低血量、缺氧、火/熔岩、停止立即撤销。观察与拓扑更新保留。
- 已在运行的夜间掩体循环重查恢复窗口及夜宿必要性，不只看日出。
  不新增定时模型调用、不注入游戏指令、不更改权限或保护缓存。
- 通过项目现有 `patch-package` 机制补齐 `prismarine-item@1.18.0` 的
  组件附魔读取，将 `{enchantments:[{id,level}],showTooltip}` 转成消费者
  既定的 `[{name,lvl}]`，保留原组件、实际等级和旧 NBT 行为。

**可证伪预测。** 外部主脑不会只因天黑而重新获得一个预防夜宿任务；
明确保护区无进展时，不会紧接着用另一反射继续挖同一圈墙；紧急情况仍可
撤销让位。附魔铁镐与头盔组合可以通过真实 Mineflayer `digTime`，且效率与
水下速掘等级仍传到方块计时器。不能用“命令派发成功”证明任务已完成。

**验证。** 夜间所有权修复前两项回归失败，修复后相关 55 项通过；另加
运行中收到外部所有权后结束长等待的回归，最终夜间/附魔聚焦 8 项通过。附魔原
getter 的隔离回放复现两项失败，包括线上同款 concat 报错，修复后 3 项
通过。fork 完整测试 761 项、实际运行树 706 项通过，修改文件语法检查通过。补丁另作独立原文
应用与最终哈希核验。私人日志在 `runtime/tts-context-20261011-1556`。

**风险及归因。** 外部主脑现在需要根据真实时间、威胁、掩体、生命与工具
判断是否继续任务、室内活动或避险；它仍可能规划失败。没有关闭真实威胁
反射，也没有改变独立模式的夜间优先级。地表回归发生在原生重载前，不能
归因于本次夜间修改。运行验收须观察实际入夜、紧急抢占和自然任务结果。
