# 本地 LLM 部署优化：Strata / Qwen 与 Minecraft Agent

记录日期：2026-10-10。

这批优化面向本地部署，已在单张 RTX 3090、Strata、
`qwen3.8-flash-next-iq3_xxs` 的共享推理服务上验证相关行为。
目标是减少每轮重新计算的输入 token、保留可复用上下文，并减少后台请求造成的等待。
游戏原生 Agent 与 N.E.K.O. 主脑的改动一起保存在本 fork；主脑改动通过配套补丁交付。
这不是整场游戏的速度或无人值守成功率保证，其他引擎、模板和硬件需要分别验证。

通用的上下文组织、观测分页和元数据诊断也可能用于其他模型。
Strata 专用的 system 边界、检查点参数和后台准入要求
`NEKO_LOCAL_STRATA_PREFILL=1`，且服务地址为 **HTTP、loopback、18030 端口**。
其他端点和未启用配置沿用原适配行为，不能直接照搬 Strata 参数到云端 API。

## 启用方式

先按[配套补丁说明](../integrations/project-neko/README.md)应用插件与主脑补丁，
再在对应进程的启动环境中设置以下开关。它们不是向正在运行的进程发送的控制命令：

```powershell
# 原生 Minecraft 与 N.E.K.O. 主脑各自继承这个本地策略开关。
$env:NEKO_LOCAL_STRATA_PREFILL = '1'

# 可选：分别启用原生端和主脑端的元数据计时。
$env:MC_LLM_TIMING = '1'
$env:NEKO_LLM_TIMING = '1'
$env:NEKO_LLM_PROMPT_AUDIT = '0'

# 普通自主目标后移实验没有证明收益，保持关闭。
$env:MC_SELF_PROMPT_TAIL = '0'
```

本地 OpenAI 兼容地址示例为 `http://127.0.0.1:18030/v1`。
完整观测分页另由 Minecraft 插件的 `[game_agent]` 配置
`reference_paging_enabled=true` 启用，不依赖原始提示审计。
分页保留三个快照，TTL 为 180 秒；回复明确标记年龄、不完整内容和源数据截断。
未读取或已过期的数据必须视为未知，不能把分页当作已经理解了所有资料。
服务器欢迎、保护反馈、当前任务约束和最近动作结果仍须进入实际决策上下文。

诊断日志字段、存放位置和范围见[客户端计时说明](llm-client-latency.md)。
原生端首个内容时间未知；主脑首个流片段不等于可执行指令。
服务端没有请求关联的排队计时时，将未解释的 SDK 时间记为未归因等待，不能冒称 FIFO 等待。
主脑适配器尚未接收任务版本，日志明确记为未知；不要据此声称实现了跨客户端任务关联。
计时不保存提示、回答、思考正文或凭据，也不增加诊断用模型心跳。

## 共享服务的调用方与思考设置

下表是此次本地试跑的分工记录，不是自动应用到所有安装的角色配置。
原生 profile 的 `model`、`code_model`、`vision_model` 可以分别配置参数，
`reasoning_effort` 在每次请求中生效；不同思考模式可能使用不同的缓存前缀。

| 请求来源 | 路线 | 此次设置 |
| --- | --- | --- |
| 原生执行决策、聊天、记忆总结及现有判断调用 | 同一本地 Qwen 服务 | `none`；聊天/执行输出上限 2048 |
| 原生生成脚本 | 同一本地 Qwen 服务 | `low`，思考预算 512；输出上限 3072 |
| N.E.K.O. 主脑的 Minecraft、普通对话及可选后台请求 | 同一本地 Qwen 服务 | 当前本地提供方默认 `none`；可选后台请求受准入约束 |
| 按需截图理解 | 同一本地 Qwen 服务，模型与图像编码均在 RTX 3090 | `none`；不为提高 GPU 利用率增加截图调用 |
| DSH observer / diagnoser / reviewer | 独立线上 `deepseek-flash` | 三角色串行、`low`；不回退到本地模型，见[监工说明](dsh-supervisor.md) |

NEKO Live 将观众消息交给主脑处理，并不因此多加载一个游戏模型。
语音识别和语音合成不等同于这台 Qwen 的聊天请求槽位。
游戏身体仍只有一个决策/执行所有者，增加模型并发不应产生互相打断的行动计划。

这里的 **16 个会话缓存槽位与 1 个实际推理并发是两件事**。
会话缓存预算位于主机内存，用于保存可恢复状态，并非同时驻留显存的推理槽位。
当前引擎按前缀匹配与可用性自动选择，
本次没有实现“游戏固定第一个槽、主脑固定第二个槽”的调用方保留接口。
引擎只有一个显式固定前缀，因此由 Minecraft 主脑持有；原生外部任务执行依赖其独立 system
检查点，不再声明另一个 pin。视觉或后台调用不能随意替换该 pin。

未来若测试双并发，应保持共享缓存池，分别测单独游戏与独立后台重叠两种负载。
新输入准入仍可能串行，并发会占用额外会话显存；默认批量解码的 MTP 行为也与单请求不同。
模型无关的状态读取和准备可以并行，但“严格按游戏优先级调度全部调用方”仍需另行实现。
不能只根据 GPU 利用率低、首字更快或总 tokens/s 更高判定游戏等待减少。

## 已有证据与限制

- 同一批 12 份请求的观测投影比较，平均输入减少 **56.0%**；
  第一份从 27856 降到 11521 token。这是输入量变化，不是端到端延迟减少 56%。
- 独立 system 边界的一次四请求对照中，变化后缀请求的新处理输入从 6108 降到 148，
  完整返回约从 6.0 秒降到 0.9 秒；仅输出一个丢弃的 token，不能代表真实游戏指令耗时。
- 普通自主目标后移的八请求实验扩大了文本共同前缀，但目标变化时仍零复用，
  两种格式均约 4.2 秒，因此 `MC_SELF_PROMPT_TAIL` 保持关闭。
- 自然工作负载中，高复用组的准备到命令验证中位数为 1.063 秒，
  部分复用组为 4.434 秒。任务与输出不同，这不是修改前后的 A/B 提速结论。

复现方法、样本量、验证范围和原始指标见
[输入处理报告](neko-llm-prefill-2026-10-10.md)、
[目标位置实验](llm-goal-position-experiment.md)和
[自然负载及并发观察](llm-client-latency-observations-2026-10-10.md)。
这些检查不能替代命令前置条件、失败退出、停止行为与实际任务成果验收。

记录这些结果时的部署基线为：单 RTX 3090、原 IQ3_XXS 权重、262144 / INT8 KV、
23 workers、PCIe 0、MTP 0.7，以及 5120 MiB / 16 槽 / 2560 MiB floor 的会话缓存。
这是比较实验的固定条件，不是每台机器都应采用的推荐值；本次没有再扩大缓存或提高并发。
每次实验只改一个变量，保留模型进程代际边界，比较完整等待、新处理 token 和任务有效性。
命令说明压缩、无工具后续回复的必要性、记忆/冷却等待拆分及双并发均是后续独立工作。
