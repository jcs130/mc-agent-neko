# 相同失败动作的有界交回

2026-10-11 11:05（北京时间）检查当前原生会话的实际命令回执，看到
`!tradeWithVillager` 连续八次返回相同错误：

```text
Action failed: !tradeWithVillager did not complete successfully.
Action output:
Not enough payment items at the received current price. No trade executed.
```

11:08 读取该登录会话归档，已有78条相同错误，计数覆盖该会话归档而不是
一段精确的78次连续尝试。检查材料与位置没有相应进展。付款不足是实际报价
条件下的正常拒绝，不能据此要求服务器修复或断言没有其他可卖物资。

已有查询保护能在五次相同 `!stats` 后交回任务，但失败动作会清除查询计数。
原生无限响应循环将发出命令当成继续条件，因此没有针对这条重复失败路径
的短周期退出机会。

此次仅修改既有任务控制器和命令完成边界，不改变模型、提示、交易策略或
游戏操作。相同的已验证模型动作、参数、完整明确失败与实际测量状态连续
三次后提醒，五次后以动作空转失败交回所有者，并保留实际失败证据。
变化的结果、参数、位置、库存、生命、饥饿或维度重开计数；查询、玩家命令、
成功、未知测量和实际身体忙碌清除计数。计算发生在原动作完成以后，不用
新定时器打断等待、挖掘或其他正常长动作；迟到回执不能结束替代任务。

源码红绿回归：旧实现24通过、2失败；修改后49项相关回归、751项完整回归
通过，`node --check` 与 `git diff --check` 通过。日志只保存检查元数据与
代码验证结果，运行诊断不保存提示、模型回答、思考或凭据。

## 部署与验收

当前阶段为 prepared。只允许在既有所有权及安全空闲检查通过时重载原生
子进程，保留主脑、插件、模型、语音和 MindServer。没有安全边界就保留
当前服务连续运行，不为加载此改动打断健康操作。

此保护只验证同一任务内部重复失败能够退出。主脑可能重新提交相似目标，
也可能改换方案；只有实际自然动作与任务成果能说明是否恢复有效生存。
物理脱困、交易成功、长期无人值守和最终口播不重复尚未通过本次验收。
