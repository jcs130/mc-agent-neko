# Neko 接管期间的 pin-breaker 所有权修正

记录日期：2026-10-10。适用范围是 N.E.K.O. 外置主脑驾驶原生 Minecraft Agent 的部署。

## 证据

北京时间 19:35:56 和 19:37:56，原生日志先后发出
`Pinned 15min+ — kicking the stack (forced interrupt, kick #1/#2)`。
19:30:56 的原生任务已经 END，19:32 与 19:37 插件快照均没有待执行任务；
主脑会话仍 active / ready，并在查询游戏和服务器资料。
角色 HP / 饥饿 20 / 20，有实际箱子访问、位置变化和新增 7 个铁锭的库存证据。
因此不能仅凭小范围停留把它认定为卡死。
工单 T-0003 的 occurrences 从巡检初始 88 增至修复前 90，已记录为本次修复基线。

旧日志的“15min”是固定文字；当前 pin 分支的时间阈值实际为 5 分钟。
本次保留其独立运行阈值及退避策略，不用改日志来掩盖打断。

## 机理与改动

`reflex_watchdog` 的 pin-breaker 仅通过 `_extIntentUntil` 给正在执行的管理员任务让位。
两条原生任务之间，Neko 仍拥有自主规划权，但命令租约会过期；
旧位置计时遂进入强制打断分支，设置 `interrupt_code`、取消导航，进一步还能启动强制搬迁。

修正复用已有 `agent.hasExternalAutonomyOwner()`，在外部主脑持有自主权且没有 vital 危险时，
重置 pin 窗口、kick 计数和相关升级锚点，不累积主脑规划时间。
没有提前返回整个 watchdog：窒息自救和后续紧急检查仍运行。
致命状态取消该让位；独立 Agent、原管理员租约、任务 deadline 与 onNoProgress 沿用原行为。
没有增加模型心跳、发送公屏聊天或手工指定游戏动作。

## 可证伪预测与验证

- 外置 Neko 在两条任务之间正常规划时，不再由此 pin 分支产生强制取消或搬迁。
- 单独运行时的真实长时间停滞仍可触发旧 pin 恢复。
- 外部主脑持有自主权时，vital 危险与窒息自救仍可执行。

[回归测试](../test/reflex_pin_ownership.test.mjs)直接运行实际 watchdog mode；
独立模式能产生 kick 的对照证明测试不是被外层 catch 静默跳过。
修改前外置规划测试失败，其他 5 项对照通过；修改后全部通过。
相关所有权、导航和目标生命周期回归 62 项通过，全量 fork 检查 648 项通过。

本次巡检另通过正式插件 API 恢复 NEKO Live，确认房间 272191 已认证、connected / listening，
并保存插件自动启动及 `live_enabled=true` 设置。保留关闭主动暖场/空闲主持/主动互动、
`auto_low_interrupt` 的配置；没有扫码或测试弹幕。房间 offline，真实观众互动仍待自然消息验证。
这些是本机运行设置，不将凭据或私人配置提交到仓库。

## 部署与归因边界

原生修正需经过现有生命周期，在新鲜、健康、白天、无近邻威胁且任务实际 END 的边界加载。
发布代码与通过测试不等于已经部署，也不等于线上工单验收完成。
维护回执使用 `services/dsh-supervisor/repair.mjs`，保存实际 SHA、检查日志及部署证据；
不足以观察下一次 pin 窗口时维持 deployed / awaiting_runtime_verification，不自动关单。
部署结果以每小时维护日志和工单回执为准。

此修正针对旧 pin 恢复链与外部自主权冲突；不据此宣称交易、工具选择、
背包整理、其他卡住机制或长期无人值守任务全部解决。
