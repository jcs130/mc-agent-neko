# Mana and abilities received before viewer startup

The Java 1.20.6 server sent an `mcagent:state` login packet with mana 26/26 and
nine abilities. `GameInformation` captured it on the action player's connection,
but the modern viewer started later inside `spawn`. The host only listened to
subsequent packets, so a real LAN Socket.IO subscriber received no `skillsState`.
This was an initialization race, rather than an absent ability schema adapter.

The adapter now takes the same connection's `GameInformation` explicitly and
passes a bounded, complete JSON login packet to the host's existing strict
parser. Foreign bots, closed observers, invalid timestamps, truncated entries,
oversized payloads and malformed schemas are rejected. Cached readings retain
their original timestamp, carry `stale: true`, and do not claim current cooldown
readiness. A later live packet replaces that reading normally. No new game
login, server command, chat or model request is introduced.

The live reload exposed a second race: packets can arrive during asynchronous
asset validation, after the adapter captured a snapshot but before the host
attached listeners. The adapter now passes a lazy lookup that the host calls
after asset startup, immediately before its synchronous listener setup. A
separate regression reproduced missing skillsState during that window.

A server spell catalogue can enrich an ability's mana cost without measuring
mana again. The importer also preserves the previous observation timestamp for
that merge; its regression first failed because the catalogue made old mana
appear freshly observed. New catalogue text remains available normally.

The host is regenerated by `scripts/import-modern-viewer.mjs` from the existing
Cortico revision and shared renderer revision
`79ddc629a7ba0c74ba064234e7928052be6dfc15`. Its recorded bundle hash is checked.
Existing renderer UI labels old mana as the last received reading; ability rows
with a null remaining cooldown display unknown rather than ready.

Validation: the early-login integration test first failed with `Missing
skillsState`. After the repair, all 13 viewer/adapter tests passed, including
local and LAN views, stale timestamp retention, malformed schema recovery,
subsequent live updates, source hash, private text, observer cleanup and skins.
These isolated tests do not establish current server-side mana freshness.

Live deployment and final runtime acceptance are recorded separately after
the viewer-only refresh; gameplay identity must remain unchanged.
