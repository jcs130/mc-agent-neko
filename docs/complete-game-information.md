# 本地部署：完整游戏上下文与固定规则审计

2026-10-12。按用户最新要求撤销有损上下文裁剪。本文覆盖 MC 原生执行器、
Minecraft 插件、插件消息桥和 Neko 主脑输入；旧文档中的摘要预算不再代表当前策略。
模型、单 3090 部署、非思考参数和本地 VoxCPM2 路线均不因此改变。

## 全量实验与用户确认的最终方向

最初直接把全部原始协议、事件和日志塞进每轮提示，实际请求达到 **945024 token**，
当前 Strata 服务提供 **32768** 上下文，返回明确的400超限错误；Agent不能行动。
这次实测否定了“解除所有截断就能直接上线”的假设，下面的全量保留指存储和明确
选择的查询结果，不代表每轮无限输入。用户随后明确选择：完整保存所有信息，每轮
提供当前事实和查询入口，细节按需读取。

`GameEvidence` 现在保存不可变、内容寻址的完整观察；新收到的事件和已遮蔽认证
参数的内部日志立即追加到私有 `minecraft-evidence/received-events.jsonl`，不等到
下一次模型调用。目录使用SDK选择的运行数据根，不写进源码目录。本机已将旧目录
逐文件校验后迁移，旧ID保持可用。换连接前及正常停止时保存最后观察。新证据无自动TTL、条数删除
或字符截断，重载后可用原ID读取。不要把该私有证据目录提交到Git。

每轮提供当前生命、饥饿、位置、全部已接收实体、库存名称/lore、保护状态、完整
交易报价、魔力和技能，以及完整服务器欢迎说明。NBT、书页、配方/进度目录、
YSM资源、旧事件及内部日志以明确的ID和JSON指针引用；这些字段不冒充空值或完整
正文。玩家当前待处理消息仍完整交付，历史消息目录保留身份、时间和原文入口，
目录本身也通过引用按需读取，不在每轮重复所有旧条目的表头。
被动状态通知只带查询索引，避免在主动决策之外再复制一份完整状态。
完成回调带匹配回执、当前生命/资源/技能和完整状态入口，不再与紧随的空闲决策
各复制一份实体/背包/窗口。实时与迟到回执、过期快照备用通知、内部日志通知均
使用明确原文索引。原生反馈中的结论与命令结果可按原生协议标记分别读取，保留
原始全文；不是重新生成的摘要。玩家当前消息和危险告警仍通过专用通道交付。
实体视图共享列名，行首保留原快照索引；不同字段集合分别成组，缺失字段与null
保持不同。所有实体的身份、收到的名字、距离、生命、装备和掉落物均在当前视图中；
每个实体的完整精确坐标和协议字段明确列在 `indexedColumns`，按行首索引和字段名
读取 `/state/nearby/entities/<index>/<column>`。没有距离/数量删除；结合原文查询可
还原每个已接收值。自身坐标仍完整提供，原生导航始终使用当前世界的真实坐标。

默认 `minecraft_observe` 返回当前事实和索引；`detail="full"` 加明确 `sections`
仍能读取原始区块。用 `evidence_id` 和 `reference_path` 可读取任意完整历史字段，
例如 `/state/inventory/slots/0/book/pages/0/text`。只有调用者显式指定 `offset` 和
`limit` 才分页，并返回 `nextOffset` 和总长度；默认不自动分页、不隐藏剩余内容。
历史证据不会覆盖当前连接的认证。超长的单个显式查询仍可能超过模型容量，需由
调用者选择书页/字段或明确分页，不启用服务端静默截断。

相同实际观察的默认视图离线估算约1.85万token，被动索引约220token；这只是提示
片段估算，不是整轮请求或速度承诺。必须以真实请求接受、工具调用及游戏进展验收。
请求计时新增每条消息的角色、文字字符数和工具调用数量，不记录正文或参数，
用于识别整轮内的重复状态与超长工具结果；计时仍不把服务端未知排队算成输入耗时。

首轮上线后，真实请求已被接受（一次29224输入token、约10.38秒），但观察仍只有
口头计划和零位移，不能据此宣称自主行动恢复。后续修改使宿主确认的执行回合
在首轮选择工具，包含 `minecraft_wait` 的明确等待/停止出口；社交回合不强制工具，
不强迫某种玩法。仅口头说“准备查”不算执行。等待按有效状态版本去重，新的玩家
事件或状态变化重新规划；停止和动作归属保持有效，状态接口显示实际等待原因。
缺少等待工具的旧插件不启用这个协议，避免只剩身体动作可选。实机已确认工具调用
被接受，但将查询结果接回模型曾达到33956/34847 token并被明确拒绝；其中旧事件
表头随历史持续增长。后续将整个历史目录变为可精确读取的入口，完整原文仍保存；
新增600条历史消息验证目录不再随旧表头占满当前决策，最后一条原文仍可读取。

原生执行器也采用同一保存/输入分离原则：控制器在接取任务时记录原始历史的起点，
执行、写脚本和视觉判断提供当前任务的完整回合及实际结果，跨任务的旧口头计划
不再反复注入新任务。完整历史和生成记忆均保留；`!historyIndex()` 查询全部目录，
`!historyEntry(index)` 精确读取任意原始回合，`!historyMemory()` 读取历史摘要。
这不是按字数或最后N轮截断；当前任务的长失败原因、调用与结果仍完整相随。
新任务边界由控制器拥有，无法用玩家文本伪造；停止与过期回合检查继续有效。

后续实机追踪还发现两条绕过索引的路径：空闲调度器把所有服务器旧回复直接拼进
每轮提醒，观察工具在当前状态之外也附上全部旧任务与服务器回执。真实请求又增长
到51449 token，后续空闲请求也持续超过32K。现在这两条路径均返回完整原文的
不可变查询入口；匹配任务ID、状态、原始时间及失败次数保持可见，旧目标和反馈
按精确路径读取。最新完成回调也使用完整回执索引，保留匹配ID与状态；重试失败任务前必须查询匹配
反馈，不能把索引当成任务成功或当前库存。回归以长反馈、完整旧目标和服务器回复
逐字取回为依据，并确认这些历史正文不会再次直接注入当前事实。

默认观察返回新鲜度、关键当前状态、资源/技能概览、完整原文索引及行动资格；选取
`sections` 时索引这些完整分区，需要正文可按具体指针读取或显式选择 `full`。
这样避免把已经提供的整份状态再追加一次。不会为了提高模型利用率
增加查询或提高心跳频率。证据通过SDK的运行数据目录保存，不使用源码旁的清单目录。
执行回合收到 `minecraft_task` 的结构化异步接取回执后，把控制权交给原生执行器，
等待真实完成/状态回调；不再追加一轮模型规划去抢同一个身体。调用和接取回执仍完整
保留，busy/failed、只有口头承诺或普通对话均不能触发这个交接。

## 证据与原因

实际任务连续打开同一村民窗口，窗口 ID 变化但报价没有变化：只收甜菜根/马铃薯，
没有任务要求的铁锭收购项。完整工具输出约 810 字符，动作管理器却只保留首尾各
250 字符，正好丢掉中间报价。读取菜单又被算成成功动作，未触发已有查询循环检测。
这不能证明服务器交易故障，也不能证明模型只因裁剪才重复。

继续追踪发现：即使前一层完整，后续状态投影、任务反馈摘要、插件消息桥、主脑
通知归一化和最终渲染仍会再次截断。完成通知甚至会因为其他字段占完预算而省掉
整个结果。这种分层裁剪不能靠增大某一个 token 数解决。

## 已撤销的裁剪

| 层 | 原有行为 | 当前行为 |
|---|---|---|
| 动作结果 | 长输出只剩首尾；中断时输出为空 | 全部实际输出消费一次；中断前已记录结果仍保留 |
| 菜单、物品、交易 | 名称/lore、报价数量、窗口字符数上限 | 完整已接收名称、lore、槽位及所有报价 |
| 书本 | 页数和单页字符上限 | 从明确选择的起始页读取所有已接收页面 |
| 原生历史 | 回合/字符投影；摘要后原文退出提示 | 保存完整原始回合；摘要只是补充，不替换原文 |
| 脚本查询 | 深度和条目裁剪、只保留几个短查询结果 | 完整可序列化公开查询结果与诊断轨迹 |
| 游戏快照 | 分区预算、长字符串、条目和深度上限 | 完整可表示的已接收状态；来源的未知/异常标记保留 |
| 实体与服务器状态 | 实体、命令、队伍、进度、属性、牌子数量上限 | 所有已接收实体；已接收服务器表不再按数量丢弃 |
| 事件突发 | 原生128/48、插件64/128等数量裁剪和120/300秒删除 | 当前连接全部已接收事件与原始时间；换维度不会清空未交付队列 |
| 插件上下文 | 不同模式裁剪后无法取回原文 | 原文保存在证据库；当前事实与完整细节入口明确区分 |
| 任务/失败历史 | 短目标、短反馈、最多若干旧任务 | 完整已接目标与匹配结果，保留原始失败和后续成功 |
| 观察工具 | 默认摘要；full 强制选择、自动分页 | 默认当前事实和明确引用；full/原文读取不静默裁剪 |
| 玩家消息 | 长消息裁剪、每次只发两条、延迟消息过期丢失 | 一次交付所有待处理消息原文；长动作不丢未交付消息 |
| 主脑桥接 | 通用200/1000/2400-token摘要及总渲染上限 | 经宿主确认来源的 MC 输入保持完整；其他插件不变 |
| 内部执行日志 | 200条缓存、90秒carry、带命令语法整行丢弃 | 完整带时间的日志作为证据；密码参数遮蔽，日志不单独触发模型 |
| 播报记忆 | 只留4句、每句240字符、300秒过期 | 保留当前会话实际播报整句，用于避免重复，不视为游戏进度 |
| 本地推理历史 | 只留最后6段主动播报，套用屏幕评论过滤 | 游戏请求保留全部合法配对消息，不做这两种文本投影 |

旧 `max_tokens` 参数仅作为接口兼容项接受，不再裁剪游戏事实。旧 reference cursor
仍可显式续读已有不可变快照，新观察不会自动变成分页。显式传入 `sections` 或
`max_events` 是调用者的查询选择；省略它们读取所有当前状态与保留事件。
完整反馈中的命令是证据，不获得执行权限，也不该被朗读到公屏。自动决策中的
历史事件和协议字段按上面的明确引用方式读取，避免把全部历史当作当前状态。

## 固定玩法规则的处理

- 去掉“最多再查询一项”的固定限制；按实际缺失事实查询，已有可靠结果后行动。
- 去掉玩法的固定优先级，不强制居民事务→公会→试炼，也不强制服务器操作后挖矿。
  已接任务、当前条件、服务器真实回执与用户目标决定下一步。
- 去掉“没有剑/斧必须先制作”的要求。没有这两种物品不等于没有战斗能力；
  判断需结合护具、服务器技能、敌人和目标。原始装备和技能信息完整可见。
- 核查夜间避险：外部 Neko 规划器持有自主权时，天黑本身不能触发原生预防性
  夜间任务。已有归属机制和开关保留，实际受伤、溺水、迫近危险仍能反应。
- 去掉“动作返回太快就重新连接”的网络处置。快速循环先取消自动恢复并返回
  证据；真实断线仍按原有适配器自动重连与私有认证。
- 同一村民重复检查新增语义核查：仅关联当前模型任务，身体空闲且完整报价已
  收到时，比较目标、实际报价、库存、位置与生命；忽略新窗口 ID。连续相同
  检查第3次提醒，第5次交回当前子任务和完整报价。真实状态变化会重置检测，
  人工检查不触发；不自动判定整个玩法无法完成，不替模型编造下一步。

## 保留的边界及依据

这些不是字符/摘要裁剪，不能为了“完整”而伪造当前事实或允许并发抢身体：

| 边界 | 保留原因 |
|---|---|
| 当前快照45秒新鲜度、连接/序号检查 | 断线或旧连接的位置/认证不能当成当前状态；过期明确为未知 |
| 连接归属、历史时间与当前状态区分 | 事件/聊天/播报不再按固定时间删除；旧事件不能证明当前位置、危险或认证 |
| 本地块采样半径4、容器搜索半径16 | 明确的世界查询范围；不声称包含未加载地图。实体保留所有已接收记录 |
| 停止/暂停、身体/任务/连接归属 | 防止过期回答、社交回调和监工抢占正在执行的动作 |
| deny/unknown 保护校验 | 服务器权限拒绝是真实规则，不应绕过；其他坐标的允许不覆盖当前拒绝 |
| 脚本沙箱、超时、调用额度、256 KiB RPC传输边界 | 限制失控执行及明确的传输容量；超限返回错误，不返回伪装完整的前缀 |
| 工具轮次、任务期限、实际无进展检测 | 有界执行与控制权交回；不能把正常长动作、窗口编号变化或低 GPU 当作故障 |
| 认证来源检查、游戏协议参数校验、私有字段隔离 | 防止玩家伪造认证、旧任务调用、泄漏密码；凭据不会进入模型上下文 |
| 视频/截图压缩、日志预览、哈希长度 | 媒体或诊断显示策略；不裁剪发送给模型的游戏文字事实 |

撤掉输入裁剪不意味着无限上下文。模型仍有真实部署容量，过长输入必须显式报错，
不能悄悄删字段并声称完整。完整原文可能增加输入处理耗时；本次不宣称提速，
不增加心跳频率、不换槽位或推理参数来掩盖问题。可无损去重相同状态通知；
同一任务中的失败、成功和未满足前提不得被摘要改写掉。

实测完整快照已超过默认512 KiB消息总线容量，默认通道会明确拒收，不能通过
裁剪来规避。本机启动配置把字节传输容量设为16 MiB；示例见
`integrations/project-neko/deployment/complete-context.ps1`，需在启动宿主前加载，
让所有子进程继承。模型上下文容量与推理参数不变；真实模型超限仍明确报错。

## 验证与部署

回归覆盖长指引/书页、40条报价、140个 NPC、180条私聊、300条事件突发、
完整目标与回执、成功摘要后原始历史、真实宿主入队与文本/语音渲染、正常动作
归属和夜间决策归属。测试应比较原始内容，不再以“符合某个小预算”作为通过依据。
另覆盖10分钟后的原始事件、换维度时未交付消息、250条带工具调用语法的完整日志、
认证参数隔离，以及过了原播报时间窗仍能看见已说过的整句。原生相关回归243项，
Python相关回归348项与42个子测试通过；完整补丁回放另行核对。

可证伪预测：报价中间内容和最后一项条件能到达模型；不同情境不会隐去关键事实；
重复菜单检查不因窗口编号变化被误认为进展。是否自然完成交易、停止重复播报、
持续生存，需要部署后多帧、任务回执和实际语音验证，不能仅凭测试通过验收。

修改分为 MC 原生提交和 `integrations/project-neko` 配套插件/宿主补丁。
必须完整回放补丁并核对最终源码树，再在安全空闲边界加载；保留本地模型、TTS
和观战进程。实际部署阶段与测试数写入同目录 manifest 和运行巡检记录。

## 回归报告 / Regression Report

原来长反馈在多个独立阶段丢失，模型可能重复检查已返回的条件。现在从原生到
宿主保留已接收原文，以时间、会话和权限标记限定其含义。主要回归风险是较长
请求增加输入耗时/内存，以及模型更易注意到旧失败；因此保留实际时间、状态、
匹配任务 ID 与“历史不是当前进度”说明，不把成功摘要作为删除原始证据的理由。

## 不拆分理由 / Why Not Split

原生、插件、消息桥与宿主渲染任一层仍截断都会破坏完整性，必须一起验收。
源码仍按原生、插件、宿主分别提交和导出，测试与文档随其契约迁移；不包含
模型更新、推理调参、UI改版或无关重构。
