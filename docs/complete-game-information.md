# 本地部署：完整游戏上下文与固定规则审计

2026-10-12。按用户最新要求撤销有损上下文裁剪。本文覆盖 MC 原生执行器、
Minecraft 插件、插件消息桥和 Neko 主脑输入；旧文档中的摘要预算不再代表当前策略。
模型、单 3090 部署、非思考参数和本地 VoxCPM2 路线均不因此改变。

## 证据与原因

实际任务连续打开同一村民窗口，窗口 ID 变化但报价没有变化：只收甜菜根/马铃薯，
没有任务要求的铁锭收购项。完整工具输出约 810 字符，动作管理器却只保留首尾各
250 字符，正好丢掉中间报价。读取菜单又被算成成功动作，未触发已有查询循环检测。
这不能证明服务器交易故障，也不能证明模型只因裁剪才重复。

继续追踪发现：即使前一层完整，后续状态投影、任务反馈摘要、插件消息桥、主脑
通知归一化和最终渲染仍会再次截断。完成通知甚至会因为其他字段占完预算而省掉
整个结果。这种分层裁剪不能靠增大某一个 token 数解决。

## 已撤销的裁剪

| 层 | 原有行为 | 当前行为 |
|---|---|---|
| 动作结果 | 长输出只剩首尾；中断时输出为空 | 全部实际输出消费一次；中断前已记录结果仍保留 |
| 菜单、物品、交易 | 名称/lore、报价数量、窗口字符数上限 | 完整已接收名称、lore、槽位及所有报价 |
| 书本 | 页数和单页字符上限 | 从明确选择的起始页读取所有已接收页面 |
| 原生历史 | 回合/字符投影；摘要后原文退出提示 | 保存完整原始回合；摘要只是补充，不替换原文 |
| 脚本查询 | 深度和条目裁剪、只保留几个短查询结果 | 完整可序列化公开查询结果与诊断轨迹 |
| 游戏快照 | 分区预算、长字符串、条目和深度上限 | 完整可表示的已接收状态；来源的未知/异常标记保留 |
| 实体与服务器状态 | 实体、命令、队伍、进度、属性、牌子数量上限 | 所有已接收实体；已接收服务器表不再按数量丢弃 |
| 事件突发 | 原生128/48、插件64/128等数量裁剪和120/300秒删除 | 当前连接全部已接收事件与原始时间；换维度不会清空未交付队列 |
| 插件上下文 | decision/running/social/survival 分别隐藏信息 | 所有模式保留相同原始事实；调度提示仍区分模式 |
| 任务/失败历史 | 短目标、短反馈、最多若干旧任务 | 完整已接目标与匹配结果，保留原始失败和后续成功 |
| 观察工具 | 默认摘要；full 强制选择、自动分页 | 默认完整；两种旧 detail 名称均保留完整内容 |
| 玩家消息 | 长消息裁剪、每次只发两条、延迟消息过期丢失 | 一次交付所有待处理消息原文；长动作不丢未交付消息 |
| 主脑桥接 | 通用200/1000/2400-token摘要及总渲染上限 | 经宿主确认来源的 MC 输入保持完整；其他插件不变 |
| 内部执行日志 | 200条缓存、90秒carry、带命令语法整行丢弃 | 完整带时间的日志作为证据；密码参数遮蔽，日志不单独触发模型 |
| 播报记忆 | 只留4句、每句240字符、300秒过期 | 保留当前会话实际播报整句，用于避免重复，不视为游戏进度 |

旧 `max_tokens` 参数仅作为接口兼容项接受，不再裁剪游戏事实。旧 reference cursor
仍可显式续读已有不可变快照，新观察不会自动变成分页。显式传入 `sections` 或
`max_events` 是调用者的查询选择；省略它们读取所有当前状态与保留事件。
完整反馈中的命令是证据，不获得执行权限，也不该被朗读到公屏。

## 固定玩法规则的处理

- 去掉“最多再查询一项”的固定限制；按实际缺失事实查询，已有可靠结果后行动。
- 去掉玩法的固定优先级，不强制居民事务→公会→试炼，也不强制服务器操作后挖矿。
  已接任务、当前条件、服务器真实回执与用户目标决定下一步。
- 去掉“没有剑/斧必须先制作”的要求。没有这两种物品不等于没有战斗能力；
  判断需结合护具、服务器技能、敌人和目标。原始装备和技能信息完整可见。
- 核查夜间避险：外部 Neko 规划器持有自主权时，天黑本身不能触发原生预防性
  夜间任务。已有归属机制和开关保留，实际受伤、溺水、迫近危险仍能反应。
- 去掉“动作返回太快就重新连接”的网络处置。快速循环先取消自动恢复并返回
  证据；真实断线仍按原有适配器自动重连与私有认证。
- 同一村民重复检查新增语义核查：仅关联当前模型任务，身体空闲且完整报价已
  收到时，比较目标、实际报价、库存、位置与生命；忽略新窗口 ID。连续相同
  检查第3次提醒，第5次交回当前子任务和完整报价。真实状态变化会重置检测，
  人工检查不触发；不自动判定整个玩法无法完成，不替模型编造下一步。

## 保留的边界及依据

这些不是字符/摘要裁剪，不能为了“完整”而伪造当前事实或允许并发抢身体：

| 边界 | 保留原因 |
|---|---|
| 当前快照45秒新鲜度、连接/序号检查 | 断线或旧连接的位置/认证不能当成当前状态；过期明确为未知 |
| 连接归属、历史时间与当前状态区分 | 事件/聊天/播报不再按固定时间删除；旧事件不能证明当前位置、危险或认证 |
| 本地块采样半径4、容器搜索半径16 | 明确的世界查询范围；不声称包含未加载地图。实体保留所有已接收记录 |
| 停止/暂停、身体/任务/连接归属 | 防止过期回答、社交回调和监工抢占正在执行的动作 |
| deny/unknown 保护校验 | 服务器权限拒绝是真实规则，不应绕过；其他坐标的允许不覆盖当前拒绝 |
| 脚本沙箱、超时、调用额度、256 KiB RPC传输边界 | 限制失控执行及明确的传输容量；超限返回错误，不返回伪装完整的前缀 |
| 工具轮次、任务期限、实际无进展检测 | 有界执行与控制权交回；不能把正常长动作、窗口编号变化或低 GPU 当作故障 |
| 认证来源检查、游戏协议参数校验、私有字段隔离 | 防止玩家伪造认证、旧任务调用、泄漏密码；凭据不会进入模型上下文 |
| 视频/截图压缩、日志预览、哈希长度 | 媒体或诊断显示策略；不裁剪发送给模型的游戏文字事实 |

撤掉输入裁剪不意味着无限上下文。模型仍有真实部署容量，过长输入必须显式报错，
不能悄悄删字段并声称完整。完整原文可能增加输入处理耗时；本次不宣称提速，
不增加心跳频率、不换槽位或推理参数来掩盖问题。可无损去重相同状态通知；
同一任务中的失败、成功和未满足前提不得被摘要改写掉。

## 验证与部署

回归覆盖长指引/书页、40条报价、140个 NPC、180条私聊、300条事件突发、
完整目标与回执、成功摘要后原始历史、真实宿主入队与文本/语音渲染、正常动作
归属和夜间决策归属。测试应比较原始内容，不再以“符合某个小预算”作为通过依据。
另覆盖10分钟后的原始事件、换维度时未交付消息、250条带工具调用语法的完整日志、
认证参数隔离，以及过了原播报时间窗仍能看见已说过的整句。原生相关回归243项，
Python相关回归348项与42个子测试通过；完整补丁回放另行核对。

可证伪预测：报价中间内容和最后一项条件能到达模型；不同情境不会隐去关键事实；
重复菜单检查不因窗口编号变化被误认为进展。是否自然完成交易、停止重复播报、
持续生存，需要部署后多帧、任务回执和实际语音验证，不能仅凭测试通过验收。

修改分为 MC 原生提交和 `integrations/project-neko` 配套插件/宿主补丁。
必须完整回放补丁并核对最终源码树，再在安全空闲边界加载；保留本地模型、TTS
和观战进程。实际部署阶段与测试数写入同目录 manifest 和运行巡检记录。

## 回归报告 / Regression Report

原来长反馈在多个独立阶段丢失，模型可能重复检查已返回的条件。现在从原生到
宿主保留已接收原文，以时间、会话和权限标记限定其含义。主要回归风险是较长
请求增加输入耗时/内存，以及模型更易注意到旧失败；因此保留实际时间、状态、
匹配任务 ID 与“历史不是当前进度”说明，不把成功摘要作为删除原始证据的理由。

## 不拆分理由 / Why Not Split

原生、插件、消息桥与宿主渲染任一层仍截断都会破坏完整性，必须一起验收。
源码仍按原生、插件、宿主分别提交和导出，测试与文档随其契约迁移；不包含
模型更新、推理调参、UI改版或无关重构。
