# 本地推理槽位对照实验（2026-10-10）

本报告针对共享 RTX 3090 的 Strata / Qwen3.8-Flash-Next 部署。
实测后保留 **1 路推理、16 个 RAM 会话缓存槽位**，恢复原配置；这是本次已测配置中的部署选择，
没有证明全局最优，也没有把保留原配置描述为一次游戏提速。
目标是缩短游戏请求取得完整、有效指令的等待时间，同时检查单请求退化、回答有效性和内存。
这里的推理槽位是 `parallel` / `concurrency.serving`，与 RAM 会话缓存的 16 个槽位不同。
这是单机、合成场景实验，不能代替真实游戏的任务完成率或直播体验验收。

## 环境与固定条件

- Windows 11 Pro 10.0.26200，i9-13900K（24 核 / 32 逻辑处理器），2×32 GiB DDR5-5600；
  OS 可用物理内存约 63.58 GiB。文本和视觉编码均配置为 GPU 0 / RTX 3090 24 GiB，驱动 617.42。
- Strata 0.1.41，源码 `fb58e0dbc8399662c0e47c76578c6e878b14f6cf`；IQ3_XXS 权重。
- Node.js 22.22.1；引擎二进制 SHA-256 为
  `17DABC6A49746AA22BEEBDF354923BA5EEB21AFFC6597C6976AC430E46671518`。
- 上下文 262144，INT8 KV，23 workers，PCIe fraction 0；solo MTP 4，接受阈值 0.7。
- 会话缓存 5120 MiB / 16 entries / 2560 MiB floor；保留连续执行的原生检查点。
- 固定 `temperature=0`、`top_p=1`、`seed=1234`、`reasoning_effort=none`；输出上限按调用类型固定。
- DSH 使用独立线上模型；没有为了实验迁移游戏或视觉到其他显卡。

## 方法与边界

测试工具 [bench-local-inference.mjs](../scripts/bench-local-inference.mjs) 只接受 HTTP loopback。
它使用仓库的命令目录和解析器构造离线游戏场景，**不会执行模型返回的命令**，
不会发送游戏聊天、弹幕，不会设置 `strata_prefix`、修改配置或取消其他客户端的请求。
公开数据只保留计时、token 计数、有效性和配置元数据，不保存提示、回答、思考或凭据。

当前 runner 先依次预热全部四类目标，再预热交替与三调用方场景，随后执行四轮；
每轮分别检查背包、停止、坐标导航、保护区失败退出。
游戏指令输出上限 256；后台证据摘要 1024；观众解释 160。
比较五种情况：游戏独占、后台与游戏交替、后台提前 400 ms、游戏提前 400 ms、
后台/游戏/对话依次相隔 400 ms。全部预热请求不进入中位数。
每轮使用相同任务、模型参数和后台资料；不同目标会改变尾部，固定命令目录保持原顺序。
先期 `baseline-smoke`、`baseline-1`、`baseline-controlled` 和默认 `parallel-2` 使用旧 runner，只预热背包目标；
它们的首次目标切换可能是冷输入，不能据solo汇总直接断言并发导致退化。
数据中的 `warmed_fixtures` 明确区分版本；冷输入与自然流量干扰均保留。
`parallel-2-mtp` 与最终 `baseline-retest` 使用完整四目标预热。
因此 MTP 与默认双并发之间也包含方法变化，不能把差值全部归因于 MTP。

游戏提示使用原生命令目录的代表性子集，没有连接机器人去初始化物品注册表，也没有加载线上角色全部技能与历史。
因此实际 token 数和耗时以数据文件为准，不能直接推算此前约 1.1 万或 2.9 万 token 的线上请求。
指令验收检查命令名与准确参数；失败退出必须给出非空原因。摘要仅检查证据 ID 是否齐全，
对话检查中文和不含动作指令；这不是对全部语义正确性的证明。

请求总数变化或引擎代际变化会标记整组受到干扰，失败与受干扰样本仍保留。
汇总分别给出无干扰中位数和包含自然流量的中位数，不能把后者解释为纯粹的槽位因果收益。
曾通过原有开关与会话暂停流程尝试暂缓自主规划，但前端自动恢复会话，无法保证隔离，
已恢复自主开关；该时间窗的基线独立标记。后续实验保留自然调用，不反复争抢会话所有权。
原生游戏、主服务、插件、生存反射和守护进程保持运行；需要切换时只在无活动推理的边界重载模型。
这不保证其他客户端随后不会发来请求。模型重新加载约需 80–90 秒，期间存在服务不可用窗口；
自然调用统计排除加载窗口，保留各统计窗中的错误、取消和过时结果。

`total_to_validated_ms` 从序列化已构造好的请求开始，到完整 SSE 返回并通过离线校验结束。
它包括客户端等待，**不包括**真实应用收集游戏状态或构造原始提示的时间。
首个非空 `content` 与思考片段分别计时，首字不代表有效指令。
服务端未提供可关联排队时间或分阶段计时时记为 `null`，不根据不匹配的日志推算 FIFO 等待。
每 500 ms 采样系统RAM与3090显存总占用，包含其他进程；
报告的是观测峰值，可能漏掉更短的峰值，不能把系统总占用当作模型私有内存。
样本少于 20 时不报告 p95；四轮不同任务的中位数也不能视为充分的尾延迟统计。
合成后台摘要直接提交到模型，刻意绕过应用的可选后台准入以施加压力；
其比例和长输出不能当作日常陪播调用分布，也不能把压测期间的等待当作常态游戏延迟。

## 复现

先确认 `/v1/status` 的模型已加载且 `concurrency.serving` 与标签一致。
仅在没有活动推理时，通过部署者自己的生命周期流程切换配置并重载；测试脚本不会代劳。
不要为了测试停止服务器、重开世界或同时启动第二个游戏执行者。

```powershell
node scripts/bench-local-inference.mjs --label baseline-1 --expect-slots 1 --rounds 4 --min-free-mib 2560 --out D:/bench/baseline-1.json
node scripts/bench-local-inference.mjs --label parallel-2 --expect-slots 2 --rounds 4 --min-free-mib 2560 --out D:/bench/parallel-2.json
node scripts/bench-local-inference.mjs --label parallel-2-mtp --expect-slots 2 --rounds 4 --min-free-mib 2560 --out D:/bench/parallel-2-mtp.json
```

双并发在当前模型 JSON 顶层设置 `"parallel": 2`；批量 MTP 是另一次实验，
仅在原 `args` 后添加 `"--batch-mtp"`。不要覆盖权重路径、视觉设置或其他原有参数。
撤销实验时恢复原先的 `parallel` 与 `--batch-mtp` 设置，等待空闲再重载。
请求数可能被引擎按内存限制夹紧，不能把“要求两路”当作“实际两路”。

`--min-free-mib` 是可选的基准准入保护，默认 0；读数未知或低于所设空闲下限时停止新增合成请求。
已经发送的请求自然结束，再保存结果；不会取消其他客户端，也不是全局 RAM 硬上限。
本次先期数据没有该保护，观察到双并发 MTP 的内存压力后才加入；最终单并发复测设置 2560，未触发。
上面的命令用于后续有保护的复现，不声称历史双并发实验已受其保护。

槽位共享，并不按 Minecraft、主脑或视觉保留。长输入仍需计算，准入阶段仍有串行部分；
增加槽位不能代替稳定前缀、控制上下文和后台准入。
引擎机制见 [Strata BATCHING](https://github.com/Niko1221/Strata/blob/fb58e0dbc8399662c0e47c76578c6e878b14f6cf/docs/BATCHING.md)，
结果记录按其 [社区测试规范](https://github.com/Niko1221/Strata/blob/fb58e0dbc8399662c0e47c76578c6e878b14f6cf/docs/COMMUNITY_BENCHMARKS.md) 保留失败、版本、硬件和统计边界。

## 测量结果与部署结论

共完成 **248 个合成请求，其中 210 个计入测量**；另有一次内存保护测试，没有发送推理请求。
每个正式配置四轮、40 个测量请求；初始 smoke 为一轮、10 个。
248 个合成返回全部通过上述结构校验，不能据此推断真实游戏没有错误或任务均已完成。
完整元数据见 [JSON 数据](benchmarks/local-inference-slots-2026-10-10.json)，包括先期基线、预热、
每个请求的 token 与计时、受干扰标记、缓存计数、失败字段、模型代际及采样资源峰值。

下表是包含自然流量的游戏指令等待中位数，每格 4 个测量请求。
括号为排除受干扰组后的样本数；括号外的时间不能直接用于因果 A/B 提速比较。

| 配置 / 数据标签 | 实际推理路数 | 专家缓存 MiB | 系统 RAM 峰值 GiB | 后台先行时游戏等待 s | 三调用方时游戏等待 s |
| --- | ---: | ---: | ---: | ---: | ---: |
| 原单并发复测 `baseline-retest` | 1 | 12503 | 55.11 | 8.33（4） | 7.93（4） |
| `parallel-2` | 2 | 5018 | 60.88 | 6.53（2） | 10.95（1） |
| `parallel-2-mtp`，请求开启批量 MTP | 2 | 4254 | 63.54 | 7.20（0） | 12.99（0） |

默认双并发的后台先行场景有两个无干扰样本，中位数 6.26 秒，显示可能存在局部收益；
但三调用方等待、长输出吞吐、自然流量差异与资源成本不支持直接推广为常用配置。
两个双并发配置的合成后台摘要等待中位数分别为 43.01、66.64 秒，单次最长 108.23、109.11 秒；
它们包含自然调用重叠，不能称为纯 FIFO 等待或日常陪播延迟。

最终单并发复测的 20 个测量组、40 个请求均未检测到其他请求混入。
该轮游戏单独执行中位数 **0.357 秒**，后台与游戏交替为 0.391 秒，游戏先行为 0.463 秒；
后台摘要中位数 8.17 秒。四目标均已预热，但后缀变化仍有不同输出长度。
它说明缓存命中后的短指令本身可以很快，也说明先发的长后台请求仍会造成约 8 秒等待。
这一轮的自然流量明显更安静；不能拿它与双并发混合流量直接算提速百分比。

MTP 配置的观测系统 RAM 峰值 **63.54 GiB / 约 63.58 GiB 可用物理内存**。
未据此声称发生 OOM；但余量已很小，专家缓存也由 12503 MiB 缩至 4254 MiB。
这是继续扩大并发的实际约束。因此没有测试三路，没有证明三路不可运行。
16 个会话缓存项和预算在各配置中保持不变，没有为并发实验增加缓存。

## 自然调用的辅助观察

下面按实际 SDK 发送时刻划分窗口；只对 `command_ready` 计算准备到命令验证的中位数。
它不是游戏任务完成时间，也不包含动作执行。窗口长度、任务、输入与自然流量均不同，
并受合成压测影响；最终复测窗口中部分自然请求在测量组之外发生。

| 配置窗口 | 命令有效样本 | 准备至命令验证中位数 s | 输入 / 新处理 token 中位数 | 其他执行结果 |
| --- | ---: | ---: | ---: | --- |
| 原单并发，18:00–18:28:24 | 38 | 3.62 | 10579.5 / 2337 | 无 |
| 双并发，18:29:45–18:50:13 | 64 | 5.39 | 12119 / 3059 | conversation 11、invalid_command 1、stale 2 |
| 双并发 MTP，18:51:32–19:12:33 | 10 | 5.17 | 11737 / 3629.5 | 无 |
| 恢复单并发，19:14:05–19:22:29 | 4 | 4.60 | 9926 / 2201 | stale 1 |

以上时间为北京时间。第一窗包含尝试暂停规划的时间，不能视为始终相同的活动量。
主脑还实际发出主动对话、情绪及对话选项请求；完整分类在 JSON 的 `natural` 中。
双并发窗口主脑有 1 个 error、2 个 cancelled，MTP 窗口有 1 个 cancelled，
恢复窗有 1 个 cancelled；保留记录，未把它们全部解释为槽位故障。
现有证据没有显示双并发稳定缩短了真实游戏的完整等待。
