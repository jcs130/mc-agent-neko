# 保护建筑内的脱困交接

2026-10-12 巡检复现：身体位于村庄建筑内部，`ENTOMBED` 反射不断尝试
挖墙，服务器对相同附近目标返回 `village_structure`。连续观测只有不足
一格的晃动，生命和饥饿均为 20，没有真实挖掘或外部技能在执行。
旧交接逻辑仅核对脚下地板的挖掘拒绝；地板未被拒绝而墙体被拒绝时，
它无法进入交接窗口。身体持续呈现 `mode:mobility`，主脑判断为忙碌，
普通事件仍能触发目录查询，却无法获得正常的空闲执行机会。

新的原生逻辑只记录 `guardedDig` 实际失败后、保护缓存确认拒绝的准确
目标。独立观测窗口要求明确受困状态、至少两次不同时间的拒绝、至少
三个观测，以及持续 15 秒不足两格的位移。轮换墙体目标不会清空原地
停滞的证据；它也不会据此断言所有出口均受保护。

符合条件后，反射暂停重试 60 秒，发送一次
`protected-confinement-stall`。插件仅在新鲜遥测确认身体已经空闲时
接受这个交接，沿用事件调度、最新用户授权与停止状态检查，给执行
决策提供实际保护原因。它不能自行授权破坏、编造技能、接受委托或
证明已经脱困。新的实际动作、挖掘、使用物品、危险、位移、世界变化、
过期证据和保护状态变化均撤销交接；独立原生模式不使用这个窗口。

这是为本地部署保留有效执行机会的修复，不增加模型并发、思考深度或
周期调用。原始游戏信息、聊天、任务记录与按需查询入口保持完整。
既有的地板避险与游泳交接逻辑保持独立。

验证：修复前原生新用例 5 项失败、插件新用例失败；修复后相关原生
107 项通过，完整 Minecraft 插件 284 项及 47 个子测试通过，变更的
Python 文件通过 Ruff。测试覆盖真实生产 dig 拒绝路径、原生调度入口、
遥测交接与过期、旋转目标、真实工作归属及危险撤销。

北京时间 08:10 在连续两次身体空闲、语音结束的观测之后，沿用原生
控制器更换本任务的游戏子进程并正规重载 Minecraft 插件。主脑、模型、
视觉、语音、桌面、观战与监工保持运行；守护进程仅在操作期间有界暂停。
原生运行版本为 `825ba05a`，插件来源为 `74593941`。

实际遥测随后出现新的 `protected-confinement-stall` 窗口。主脑自然
派发寻找合法出口的身体任务，人物相对部署后的原位置移动 16.8 格，
受困状态变为 `FREE`，生命和饥饿均为 20。维护过程没有注入游戏动作。
T-0082 的验证仅覆盖交接和实际位置恢复，不自动关闭工单。

这次身体任务仍在截止时间结束并报告失败，不能把位移当作任务正确
结束。此前大背包任务也报告窗口变更或未验证，连续五次转移失败；
已核对实际参数为整数，窗口失效的触发来源仍待跟踪。这些问题以及
持续委托完成保持开放。11 个自然语音周期收到完整播放回执，未见
同一周期重复播放；仍有两组文本重复生成，需要与播放故障分开判断。

现场证据保存在私有巡检目录，仅记录进程身份、协议、位移、回执、
计时及哈希，不将提示、回答、思考、音色标识或凭据提交到仓库。
