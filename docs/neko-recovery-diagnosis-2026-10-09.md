# Neko 自主运行诊断（2026-10-09）

已确认的问题在 Agent 的信息处理链路。没有修改服务器、服务器权限或其他 Agent，也没有注入诊断任务、公屏聊天或技能施放。

## 已提交并部署的修复

1. **自定义物品身份丢失。** Mineflayer 已提供 1.20.6 的组件名称，但快照解析没有展开其中的 NBT 文本；原生 `!inventory` 只返回基础 ID 和数量。现在快照和背包查询共用名称/说明解析，同时保留命令需要的基础 ID。
2. **决策摘要漏掉关键补给。** 拥挤背包在 400 token 摘要里会完全降为查询链接，700 token 摘要也会漏掉后面的物品。现在独立保留镐及状态、木料、木棍、工作台/熔炉、铁料和自定义物品身份；未收到或已截断的数量不会被当成零，省略项明确计数。
3. **失败恢复依据不足。** 旧实现只保留最后一次结果，优先完成通知还可能先于被动状态到达。现在保留最多 8 条匹配任务的终态；新会话清空旧记录，外来、重复和过期回执不污染历史。完成通知优先预留最新物品状态和失败依据。
4. **已有技能不够显眼，执行提示重复。** `!goToSurface`、`!pillarUp`、`!craftRecipe`、`!serverQuery`、`!serverCommand` 本来就有，当前部署也没有禁用。命令说明前面新增按实际可用性过滤的恢复入口；本地执行档案删除重复规则，修正字面换行和引号转义。

## 仍需解决的本体传输问题

实机消息总线抓取和离线重放确认：Minecraft 插件发送的 **840 token** 通知，经过 `plugin/server/messaging/proactive_bridge.py` 的通用结果解析后只剩 **200 token**，当前背包资源和失败依据尚未到达模型就被截掉。后面的 1,000 token 回调上限无法补回已经丢失的信息。

已准备独立提案 `integrations/project-neko/proposals/minecraft-host-bridge-budget.patch`：仅对 Minecraft 的 v2 通知使用现有的 1,000 token 回调上限；其他插件、旧格式和解析行为保留。离线验证确认关键状态可保留、超大输入仍受限、其他路径不变。这份提案独立于正常插件补丁序列，**尚未应用到本体**。

N.E.K.O. 的 `CONTEXT.md` 明确要求插件任务涉及平台层时先确认，已向用户提出确认。在得到答复前不修改平台文件。
